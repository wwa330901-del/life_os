# 大系統 V1.31.0（2026-08-03）

延續 V1.30.0，代辦事項從「專案底下的一個分頁」整個獨立成頂層空間，發布 `v2.4.0`。

## 使用者需求

「代辦事項應該獨立一個空間，並且我可以選擇我新增的是個人事項還是哪個公司的哪個專案。」詳細討論後確認：全新的代辦事項空間，裡面分「個人」及「工作」——個人只需要簡單的時間、項目；工作要選哪個公司、哪個專案、時間、事項；原本專案詳情頁裡的代辦事項分頁整個拿掉，全部改到新空間管理。另外確認：

- 「工作」的專案選單只認公司空間（使用者確認個人空間不會有專案，這條路不用處理）。
- LINE 的「新增代辦事項」要能分清楚個人/工作；但「代辦事項總覽」跟早晚提醒不用拆成兩則訊息，分類標示清楚、一次回覆就好。

（同一輪稍早也重新確認了 Instagram 抓取方案維持截圖、否決帳號登入抓取，見 V1.30.0，不重複記錄。）

## 資料庫設計

`ProjectTodo` 沿用同一張表，不搬資料、不重新命名（純改名沒有使用者可見的好處，不做這個額外風險）：

- `projectId` 改成可留空，新增 `personalOwnerUserId`（可留空，`onDelete: Cascade`，使用者被刪除時個人事項一併清除）。
- 兩者恰好擇一，用一條 DB CHECK constraint 強制（`(projectId IS NOT NULL)::int + (personalOwnerUserId IS NOT NULL)::int = 1`），不只是靠應用層邏輯。
- `assignee`/`personalOwner` 兩條指到 `User` 的關聯各自要明確命名（`@relation("TodoAssignee")`/`@relation("TodoPersonalOwner")`），否則 Prisma 認不出兩條關聯要分開處理。
- `LineAccountLink` 新增 `activeTodoPersonal`（布林，預設 false）——跟既有的 `activeProjectId` 搭配，兩者選一個生效，切換一個要記得清另一個。

Migration：`20260803150000_todo_personal_ownership`。本機沒有跑起來的開發用 Postgres（Docker Desktop 沒開），改用手寫 migration.sql（沿用 RLS 那次的做法），`prisma generate` 過（不需要連線），跑 `npx tsc --noEmit` 全綠確認型別吻合實際欄位。commit+push 後跟著 `prisma migrate deploy` 自動套用到正式環境，不用手動連線執行。

## 後端

- **新的頂層 `todos` module**（`apps/api/src/todos/`）取代原本掛在 `projects` module 底下的 `project-todos.controller/service.ts`（整個刪除，改用新路由 `/todos`，不再是 `/projects/:projectId/todos`）。`TodosService.create`：`projectId` 有填 → 工作事項（驗證專案存取權，指派人要驗證是該專案成員）；沒填 → 個人事項（`personalOwnerUserId` 設成呼叫者自己）。`listAll` 一次回傳 `{ personal, work }`，`work` 依專案分組（重用既有的 `ProjectMember` 查詢）。
- **`HomeService.getTodosToday`**（首頁「本日代辦事項」小工具、也是早晚 LINE 提醒共用的查詢）改成同時撈個人+工作事項，`projectName` 對個人事項顯示「個人」——這樣 V1.30.0 才剛做好的早晚提醒不用另外拆邏輯，個人事項直接就會出現在同一則訊息裡，分類清楚。
- **LINE `代辦事項` 指令**：進入代辦事項時的專案選單現在多一個「個人事項」選項（quick-reply postback `todo:personal`），選了之後跟選專案一樣記住在 `LineAccountLink.activeTodoPersonal`，之後「新增」「代辦事項」都會依這個狀態走個人或工作路徑；「代辦事項總覽」「完成 N」維持合併顯示，只是每筆項目的分類標籤從專案名稱變成「個人」（沒有專案的項目）。
- 順手修掉一處過期註解：`展覽` 提醒流程原本寫死「代辦事項是專案綁定的，沒有個人代辦事項的位置」，這個限制已經因為這輪解除，但這輪沒有動這個功能本身（不在使用者這次的需求範圍內），只更新了註解，避免以後看到舊註解誤判。

## App（Windows）

- **拿掉專案詳情頁的「代辦事項」分頁**（`ProjectDetailScreen` 從 5 個分頁變 4 個），舊的 `project_todos_tab.dart`/`project_todos_provider.dart` 整個刪除。
- **新增頂層「代辦事項」空間**：沿用知識庫當初做好的 `SpaceSwitcherList`（本來就是為了「以後加第 4 個頂層目的地」預留的可重用元件）——新增 `todoSelected` 參數、`_SpaceRow.todo` 樣式（新的 `AppAccents.todo` 淺藍色系）；`TodoShell`/`TodoHomeScreen` 完全比照 `KnowledgeShell`/`KnowledgeHomeScreen` 的結構；`SpacePickerScreen` 首頁新增一張「代辦事項」卡片，跟知識庫卡片並列。
- **`TodoHomeScreen`** 兩個分頁：
  - **個人**：刻意做得很簡單（標題+日期兩欄，比照使用者原話「簡單的時間、項目」），沒有優先度/備註/指派人。
  - **工作**：依專案分組顯示；新增流程先跳「公司→專案」兩層下拉選單（`_CompanyProjectPickerDialog`，公司清單重用既有 `mySpacesProvider` 篩 COMPANY 類型、專案清單重用既有 `spaceProjectsProvider`，沒有新增後端端點），選完專案才進到完整表單（標題/截止日/優先度/備註/指派人，指派人清單重用既有 `projectMembersProvider`）——整個沿用舊分頁的表單/清單元件樣式（抽成共用的 `TodoTile`）。
