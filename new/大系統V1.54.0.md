# 大系統 V1.54.0（2026-08-05）

借貸/代墊列表加上實際「已結清」欄位並分頁。

## 問題

`FinanceLoan`/`FinanceAdvance` 的 `list()` 一直是把整個空間所有借貸/代墊全部撈出來，`settled` 也只是每次讀的時候在記憶體裡臨時算（本金 - 已還款 <= 0），跟之前修過的知識庫/代辦事項是同一類「無上限查詢」問題。這次要分頁，但分頁本身會踩一個坑：如果只是照 `createdAt` 排序切頁，一筆很舊、卻還沒結清的借貸，可能被排到後面幾頁，預設只顯示第一頁的「未結清」畫面就永遠看不到它——因為 `settled` 沒有真的存在資料庫欄位裡，沒辦法在查詢層直接篩選，只能整包撈出來後在前端過濾，這就跟分頁互相矛盾。

## 修正

- `FinanceLoan`/`FinanceAdvance` 都新增真正的 `settled` 布林欄位（不再只是算出來的），由 `syncSettled()` 在每個會改變未結清金額的操作後面同步：新增、登記還款/收回、編輯本金、編輯單筆還款/收回紀錄，借貸還多一個「接受互通邀請」建立對應紀錄的時候。
- `list()` 改成游標分頁（30 筆/頁），可選 `settled` 篩選——因為現在是真欄位，`WHERE settled = ...` 直接在資料庫層做，不管這筆借貸多舊，只要還沒結清就一定會出現在「未結清」篩選的第一頁。
- **既有資料回填**：新欄位遷移時先全部設 `false`，接著在同一份 migration SQL 裡直接用一次 `UPDATE ... SET settled = (本金 <= 已還款加總)` 把既有借貸/代墊的正確結清狀態算好寫回去，不是留給下次寫入才修正（不像上一版持股快取的「自我修復」寫法——這裡邏輯簡單到可以直接在 migration 裡做完整回填，不用等使用者下次操作）。
- LINE「借貸列表」「代墊列表」原本是撈全部再自己 filter 未結清，這次順便改成直接用 `settled: false` 查詢，少一次不必要的記憶體過濾。
- App 端「借貸」「代墊」分頁的 UI 行為不變（預設只顯示未結清，切「顯示已結清」看全部），底層改成游標分頁 + 捲到底自動載入下一頁（跟股票交易紀錄同一套 `ScrollController` + `loadMore()` 寫法）。

`tsc --noEmit`、既有 51 個 API 單元測試全過，`flutter analyze` 乾淨。
