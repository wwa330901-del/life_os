# 大系統 V1.23.0（2026-08-02）

延續 V1.22.0，本輪完成「LINE AI 知識蒐集中心（知識庫）」，作為 GitHub Release `v2.0.0` 發布（版本直接跳 2.0.0，使用者明確要求）。

## 背景與討論過程

使用者一開始貼了一份自己跟 ChatGPT 討論出來的完整功能需求文件，但明確表示「這段是我跟gpt溝通的東西...你看完之後要跟我討論清楚」——不是照單全收，而是要重新逐項確認。整個設計討論分成好幾輪：

1. **核心定位確認**：LINE 官方帳號只負責收訊息/網址/圖片，商業邏輯全在後端，AI 只是後端的一個服務——這點跟原始文件一致，直接採用。
2. **AI 供應商選擇**：原本以為要沿用之前談過的 Anthropic Claude，但因為這個功能大量涉及影片/圖片分析，改選 **Google Gemini**（`gemini-2.5-flash`）——Gemini 原生支援直接看 YouTube 影片、有免費額度，技術上跟費用上都比較適合。
3. **平台範圍**：IG 只抓公開預覽資訊（不登入、零風險，拿不到完整全文/留言/輪播圖）；網頁文章/PDF/YouTube 完整分析；後來又加了直接傳 JPG/PNG 圖片。
4. **分類與欄位**：使用者一開始不確定要哪些分類，後來確認「分類可以自由設定、屬性也可以自由設定」——不寫死任何分類，比照現有「專案屬性設定」那一套邏輯（使用者自己在 App 建立分類、加欄位）。使用者自己起草了一批分類草稿（美食、景點、投資學習、設計、材料、工法、人生哲學、心靈提升、人際關係、穿搭、攝影技巧、催淚影片、星座、軟體操作運用、展覽資訊），但這些完全不寫死在程式裡，純粹是 UI 層面使用者自己會去建立的東西。
5. **無法判斷分類時的處理**：AI 判斷不出分類 → LINE 回「建議新增 XX 分類」→ 使用者回「新增」就直接建立（之後自己調欄位），回一個現有分類名稱就歸類過去。
6. **地點/展覽查詢**：LINE 選單新增美食/景點/展覽三顆按鈕。美食/景點按了之後問地點，用文字比對分類裡的「地址」欄位；展覽按了直接依「結束日期」排序列出，不用輸入地點。
7. **展覽提醒**：結束日期剩 7 天內、還沒觀展的話，LINE 主動問要不要安排觀展，回「安排」再問時間、寫入行事曆；回「不安排」就標記取消。**這裡有一個限制**：使用者原本也想寫入「代辦事項」，但目前的代辦事項系統是綁定「專案」的（`ProjectTodo.projectId` 必填），展覽是個人知識庫的東西、不屬於任何專案，所以目前只寫行事曆，代辦事項的部分沒做。使用者對此提出一個後續想法：「代辦事項應該是一個獨立的空間，可以私人可以公司」——跟行事曆變成獨立空間是同樣的邏輯，但這是一個影響現有系統的大改動，**明確延後到下一輪**，不在這次做。
8. **分享/公開機制**：這是討論最久的一塊。最終定案——
   - 公開的粒度是「分類」，不是單筆資料：整個分類設公開，底下所有資料（含未來新增的）都會被看到。
   - 公開範圍是**全系統所有帳號**，可以設黑名單擋特定人（用 email 查詢帳號）。
   - 別人的公開資料用他自己的欄位方式顯示（唯讀，不跟你自己的欄位合併），你可以選擇「存一份到我的知識庫」——這個動作其實就是把那個網址重新丟一次分析，跑進你自己的分類系統，不是直接複製欄位結構。
   - 重複資料（不同人各自記錄同一個東西）第一版不處理自動比對合併。
9. **分享按鈕**：LINE 沒有開放第三方軟體「指定分享給某人」的能力，退而求其次——App 裡的分享按鈕會讓元序生活傳一則含連結的訊息給你自己的 LINE，你自己再用 LINE 內建轉發功能傳給朋友。

在確認範圍時，我（Claude）也主動提出「先做核心，公開分享等進階功能放到第二三階段」的分期建議，但使用者最終選擇「一次做完，工程浩大就辛苦一點，做完直接升級成 2.0.0」，所以這一輪是把上面所有東西一次建置完成，沒有分期。

## 實作重點

- **後端**：`apps/api/src/knowledge/`——`KnowledgeCategoriesService`/`KnowledgeItemsService`/`KnowledgeAnalysisPipeline`/`ContentFetcherService`/`GeminiContentAnalysisService`（`AiContentAnalysisService` 介面隔離，AI 供應商可替換）/`KnowledgeExhibitionReminderService`。背景分析不用 Redis/BullMQ，`KnowledgeItem.status` 欄位本身就是任務佇列。
- **AI 呼叫**：Gemini 官方 SDK 這半年（2026-06）改版成新的 **Interactions API**（`ai.interactions.create`），舊的 `ai.models.generateContent` 還能用但不是官方現在建議的寫法——這次特地查了官方文件跟安裝套件自帶的 `.d.ts` 定義才確認正確用法，沒有單純憑訓練資料裡的印象寫。
- **PropertyType 列舉新增 `BOOLEAN`**：原本只有 TEXT/NUMBER/DATE/SELECT，這次為了知識庫的「是否已觀展」這類欄位新增，順便也讓專案屬性系統能用。
- **App 端**：`apps/windows_app/lib/ui/screens/knowledge/`——私人區/公開區瀏覽、分類欄位設定（含封鎖名單管理，新增了一個 `GET /users/lookup?email=` 的跨帳號查詢端點）、項目詳情/分享/存一份。側邊欄新增「知識庫」項目，所有空間類型都看得到（因為知識庫不屬於任何空間）。
- **LINE 選單重新設計**：從 6 顆擴充到 9 顆（3×3，畫布放大到 2500×1686）。設計過程中跟使用者來回調整好幾次——圖示曾經用 emoji 字型渲染出現「看起來歪掉」的問題（展覽/景點圖示），後來改成用 GDI+ 基本圖形手繪（矩形+三角形+圓形），保證不會因為字型渲染而跑掉；背景則是從純漸層 → 菱格紋 → 流線型曲線 → 帶光暈的流線曲線，來回調整了好幾輪，最後使用者決定「背景先素色，我自己設計好再給你」，所以目前先用素色背景上線，之後使用者設計好背景圖後只需要換圖重新上傳，不用改程式。

## 明確延後到下一輪的項目

1. **獨立代辦事項空間**（可私人可公司），順便解決展覽提醒沒有代辦事項的問題。
2. **每個使用者自己的 AI 用量各自付費（BYOK）**——目前所有人共用同一組 `GEMINI_API_KEY`，帳單全部算在系統擁有者身上；使用者主動問到這件事，之後想做的話讓每個人自己貼一組自己的 Gemini API 金鑰。
3. **每次 AI 任務的用量/成本紀錄**——這是使用者最一開始提出的設計原則之一，這輪時間關係沒做，之後不管有沒有做到 BYOK 都值得補。
