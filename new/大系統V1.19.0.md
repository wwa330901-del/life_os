## 一、Windows App 圖示

`apps/windows_app/windows/runner/resources/app_icon.ico` 從專案一開始就沒換過，一直是 `flutter create` 產生的預設圖示。素材 `Visual Design/元序應用程式標誌.png`（512x512，深咖啡底+金色「元」字+`life_os`小字，四角圓角）其實老早就存在（Google OAuth 品牌驗證那次就用過），只是沒拿來重新產生 App 圖示。

**做法**：沒有安裝 ImageMagick，改用專案本來就有的 `image` 這個 pub 套件（`pubspec.yaml` 已經是既有依賴，不用新增）寫一支一次性 Dart 腳本（`tool/_gen_icon.dart`，用完刪除，沒留在 repo）：讀 PNG → 用 `img.copyResize` 產生 16/24/32/48/64/128/256 七種尺寸 → `img.IcoEncoder().encodeImages(frames)` 包成一個多解析度的 `.ico` → 覆蓋掉 `app_icon.ico`。裝好的安裝檔（`SetupIconFile`）跟桌面捷徑的圖示都是直接讀這個 exe 內嵌的圖示資源，不用另外改安裝腳本。

**發布為 v0.21.1**（跟 v0.21.0 的定期交易功能分開發版，因為是先發完定期交易、使用者才提這件事）。照樣要先清掉 `build/windows` 再編（跟版本號凍結是同一種「CMake 增量編譯不會重新處理資源」的坑，圖示資源也一樣會被凍結）。

## 二、Windows 圖示快取的坑（新發現，跟版本號凍結是兩回事）

使用者裝完 v0.21.1、也用截圖確認新安裝檔已經跑過，桌面捷徑卻還是顯示舊的藍色圖示。一開始懷疑是沒裝到新版，但這次不是——**這是使用者那台電腦本身的 Windows Explorer 圖示快取沒更新**，跟 exe 本身有沒有正確內嵌新圖示是兩件事（那個已經確認是對的）。

**排查過程也順便發現**：這個安裝程式是 `PrivilegesRequired=lowest`（不用系統管理員權限），實際上是裝在使用者層級的 `%LOCALAPPDATA%\Programs\life_os\`，不是看 `.iss` 裡 `DefaultDirName={autopf}\{#MyAppName}` 直覺以為的 `C:\Program Files\元序`。要找真正的安裝路徑，直接讀開始選單捷徑（`.lnk`）的 `TargetPath` 最準：

```powershell
$sh = New-Object -ComObject WScript.Shell
$sh.CreateShortcut("<lnk路徑>").TargetPath
```

同一輪還遇到剛裝好的捷徑在 Windows 搜尋（打「元序」或資料夾真實英文名「life_os」）都搜不到，判斷是搜尋索引還沒跟上，跟圖示快取是類似性質但不同機制的延遲問題，用回上面找到的真實路徑直接開/直接執行繞過去。

**圖示快取最終解法**（直接幫使用者跑，比一步步教他下指令快）：

```powershell
Stop-Process -Name explorer -Force
Get-ChildItem "$env:LOCALAPPDATA\Microsoft\Windows\Explorer" -Filter "iconcache*" -Force | Remove-Item -Force
Get-ChildItem "$env:LOCALAPPDATA\Microsoft\Windows\Explorer" -Filter "thumbcache*" -Force | Remove-Item -Force
Start-Process explorer.exe
```

重開機也會解決，但使用者當下不想重開機，用這個指令立即見效，不用等。
