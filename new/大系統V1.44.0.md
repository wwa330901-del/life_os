# 大系統 V1.44.0（2026-08-05）

同一輪的三件事：專案刪除按鈕補上、LINE 選單指令補齊第一步、代辦事項比照知識庫做「不會一直堆」的優化。

## 專案刪除按鈕

後端 `DELETE /projects/:id` 跟 App 的 `ApiClient.deleteProject()` 其實早就都寫好了，純粹是專案列表畫面沒接上刪除按鈕。`project_list_screen.dart` 每張專案卡片右上角加一個垃圾桶小圖示，點下去跳確認對話框（會提示連工項/工期表/代辦/文件一併刪除、無法復原），確認後呼叫既有的 API、刷新列表。

## LINE 選單補齊（通盤檢討第 4 項，第一步）

`line.service.ts` 原本完全沒有「知識庫」這個純文字指令的處理——傳網址/圖片/影片會被分析沒錯，但打「知識庫」三個字只會落到「看不懂這個指令」。補上一個說明回覆（怎麼用、美食/景點/展覽子功能），並把知識庫這件事也加進主要的「看不懂指令」說明清單裡（原本完全沒提到）。選單按鈕圖片本身（新增知識庫/AI問答/今日行事曆三顆鍵）還沒做，等視覺設計跟使用者確認後再上傳。

## 代辦事項「不會一直堆成山」

跟知識庫分頁那次（V1.43.0）是同一類問題，但這次是使用者主動點出的：`TodosService.listAll`（個人/工作兩個分頁共用）從來沒有排除已完成項目，時間一長畫面下方全是舊的已完成項目，一路往前捲不到底。這次照使用者給的明確規格做：

- **`listAll` 改成已完成項目只保留到「完成當天」**——用既有的 `taipeiTodayRange()`（跟財務總覽/代辦總覽同一套台北時區日界算法）判斷，隔天開始就從個人/工作這兩個即時分頁消失，不是靠使用者手動切換開關。
- **新增 `GET /todos/completed`**：個人＋工作合併的完整已完成歷史紀錄，依完成時間新到舊、游標分頁（10 筆一頁），可用標題關鍵字搜尋。App 端 `TodoHomeScreen` 從 2 個分頁（個人/工作）變成 3 個，新增「已完成」分頁，搜尋框＋無限捲動，跟知識庫私人區同一套 `AsyncNotifierProvider` + `ScrollController` 寫法（`CompletedTodosPageState`，就近寫一份沒有共用抽象，理由：目前只有這兩處用得到，先不做跨模組共用）。這個分頁只能打勾取消完成／刪除，不提供編輯（已完成事項不太需要改標題/日期，保持簡單）。
- **順手抓到同一類的第二個藏得比較深的漏洞**：LINE「代辦事項總覽」（`sendTodoOverviewAllProjects`）雖然畫面上本來就有做「今日完成/今日到期/未來7天/持續性任務」的日期分桶，但抓資料那一步完全沒有 `where` 條件，是把使用者這輩子所有代辦（含已完成）整批撈出來才在記憶體裡用 `.filter()` 分桶——查詢本身沒有上限，只是畫面結果剛好被過濾乾淨，一樣是同一種「沒有上限」問題只是藏得比較隱蔽。查詢改成資料庫層先篩「未完成 or 今天完成」，跟 `listAll` 同一個過濾邏輯。

`tsc --noEmit`、`flutter analyze`、既有 51 個 API 單元測試全過。
