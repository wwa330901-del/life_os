# 大系統 V1.38.0（2026-08-04）

延續 V1.37.0，兩個相關的專案屬性功能：拖曳排序、案名自動命名規則，發布 `v2.7.0`。

## 1. 專案資料表內的屬性可以自訂排序

使用者：「每一個專案的專案資料表內的屬性我應該要能自己設定排序位置」。

**後端**：`ProjectPropertiesService` 新增 `reorder`，跟既有 `WorkItemsService.reorder`（工期表拖曳排序）一樣的「相對於某個 sibling 插入」設計（`targetId`/`insertAfter`），不是整包送排序後的陣列——把該空間所有屬性依現有 `sortOrder` 抓出來，移除被拖動的那個、插進新位置，整批 `sortOrder` 重新編號寫回去。新增 `PATCH /spaces/:spaceId/properties/:definitionId/reorder`。

**App**：`SpacePropertiesScreen`（專案設定畫面）的屬性列表改成 `ReorderableListView`（`buildDefaultDragHandles: false`，每張卡片左邊加一個明確的拖曳把手圖示，避免跟卡片上其他按鈕的點擊互相干擾）。

**做完後發現的真正問題**：拖曳排序做好之後，發現使用者實際會盯著看的「專案資料」分頁（每個專案自己的資料表單，不是「專案設定」的管理畫面）**根本不理會 `sortOrder`**——`ProjectInfoTab` 一直是把「案號、業主名稱、案名、專案地點、類型、狀態」這幾個名稱寫死在固定位置，只有這 5 個標準名稱以外的自訂屬性才會照 `sortOrder` 排。等於排序了也看不出效果。**已經一併修正**：拿掉整個寫死順序的邏輯，`ProjectInfoTab` 現在完全照 `sortOrder` 顯示所有屬性；「案名」（其實是 `Project.name`，不是屬性）固定在最上面，「簽約日期」「預計結案日」（`projectStartDate`/`projectEndDate`）固定在最下面——這三個不是 `ProjectPropertyDefinition`，沒有 `sortOrder` 可以排序，維持固定位置合理。

## 2. 案名自動擷取屬性組成建議值

使用者：「每一個專案空間屬性設定完成之後應該讓我設定案名要自動擷取那些屬性」。

**查證後發現這個功能其實已經存在，只是寫死**：`CreateProjectDialog`（新增專案對話框）本來就有「輸入業主名稱/專案地點/類型時即時組合成案名建議值，使用者打字覆蓋後就不再自動跟隨」的邏輯，但寫死只認「業主名稱」「專案地點」（TEXT）+「類型」（SELECT）這三個特定名稱的屬性，別的空間如果沒有剛好用這三個名字，這個功能就完全不會啟動。

**確認的設計**：可以手動改（自動擷取只是新建時的建議值，不會強制同步）；設定位置在「專案設定」畫面，整個空間共用一套規則。

**實作**：
- `Space` 新增 `projectNameTemplate`（`Json?`，`{ propertyNames: string[], separator: string }`，null 代表沒設定，維持原本「案名要自己打」的行為）。
- 新增 `GET/PATCH/DELETE /spaces/:spaceId/properties/naming-template`，跟屬性定義一樣掛在 `ProjectPropertiesService`（OWNER/ADMIN 可管理）。
- `SpacePropertiesScreen` 新增「案名自動命名規則」區塊：從空間現有屬性挑選（可挑任何型態，不限文字/單選），依選擇順序組合，加上一個分隔符號輸入框；清空選擇等於取消規則。
- `CreateProjectDialog` 的 `_recomputeName` 改成讀這個空間的規則（`namingTemplateProvider`），依規則裡的屬性名稱順序，抓當下使用者已經輸入的值（不論文字/數字/日期/單選都支援，不再只限定文字型態）用分隔符號組合起來，一樣維持「使用者手動輸入後就不再跟隨」的既有行為。空間沒設規則、或規則裡的屬性名稱在這個空間已經不存在了，就跟以前一樣、案名留空給使用者自己打。
