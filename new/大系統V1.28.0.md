# 大系統 V1.28.0（2026-08-02）

延續 V1.27.0，修正一個正式環境的當機問題（線上 bug，不是 Windows App 更新）。

## 問題

使用者在 App 裡輸入自己的 Gemini API 金鑰後，第一次在 LINE 丟連結測試，收到分析失敗訊息：

> 這則知識庫內容分析失敗了：404 This model models/gemini-2.5-flash is no longer available to new users.

查證後確認：Google 已經不再讓「新申請」的 API 金鑰使用 `gemini-2.5-flash`（原本選這個模型是因為便宜、支援原生看 YouTube 影片；但 Google 這邊持續在做模型世代輪替，2.5 Flash 對新金鑰已經關閉存取，2.0 系列則是直接下架停用）。這不是這套系統的 bug，是外部服務的模型可用性變動，但因為 `GEMINI_MODEL` 是寫死的常數，需要手動更新才能恢復。

## 修正

- `apps/api/src/knowledge/ai/gemini-content-analysis.service.ts`：`GEMINI_MODEL` 改成 `gemini-3.6-flash`（目前 Google 穩定版的新一代 Flash 模型，一樣支援文字/圖片/影片多模態輸入，一樣可以直接看 YouTube 影片）。
- `apps/api/src/knowledge/ai-usage.service.ts`：`estimateCostUsd` 的計價常數同步更新（`gemini-3.6-flash`：輸入 $1.50/百萬 tokens、輸出 $7.50/百萬 tokens，比 2.5 Flash 貴，但仍是目前 Gemini 家族裡穩定可用的合理選擇）。
- 桌面的 `Gemini API 收費分析.md` 同步更新模型名稱、單價與所有預估數字（單月費用預估區間大約上調到原本的 4-5 倍，仍在個人使用可接受的範圍）。

跑過 `tsc --noEmit`、既有 51 個 API 單元測試（全過，這個模組本來就沒有針對模型字串的專屬測試）、`eslint --fix` 僅限 `src/knowledge` 範圍，確認沒有其他地方寫死 `gemini-2.5-flash` 字串。

## 發布

純後端修正，Windows App 端沒有任何變動，不隨附安裝檔更新——直接 commit + push 讓 Render 重新部署即可恢復正常，不走 Windows 版號/安裝檔那一套發布流程。
