# 大系統 V1.63.0（2026-08-07，純後端）

工程財務四表模組（工程報價單／採發比價表／成控管制表／工程請款單）— 後端資料模型 + API，App 端畫面尚未實作（下一版接續）。

## 背景

工程專案內部四張財務表格的線上化：報價時的業主報價/成本、發包比價、成控追蹤（含追加減跟拆項）、廠商請款內部簽核，全部掛在既有「專案」底下。

## 資料模型

- `QuotationLineItem`（工程報價單一列工項）：單價/數量/成本單價，複價/成本複價/利潤/毛利率都是讀取時現算，不落地存。整案只會有一份（跟 Project 攤平假日曆位同一個理由），不用另外的表頭 model。
- `ProcurementComparison` + `ProcurementVendorQuote`（採發比價表）：一個專案可以有多張（每張對應一個發包範圍），廠商報價可以附檔（沿用知識庫已經在用的 Supabase Storage）。決標時選定廠商 + 決標金額（可能跟原始報價不同）。
- `CostControlRow` + `CostControlRowQuotationItem`（成控管制表一列）：跟報價單工項多對多——實際發包不一定 1:1 對應報價分項（例如 ABCD 四項可能發成 AB、CD 兩包），業主報價/預估成本用勾選的工項加總現算；連結一張採發比價表帶入實際發包金額；`CostControlAdjustment` 記錄追加/追減歷史（不是覆蓋成一個總數欄位）。
- `PaymentRequest`（工程請款單）：對應唯一一列成控列，送出時自動帶入當下的合約金額/累計已請款百分比快照。固定五關依序簽核（業務主管→財務初審→成控→總經理→會計出納，承辦人本人送出不算一關），送出時由承辦人指定各關負責人（必須是同公司空間成員）——欄位直接攤平在同一張表（固定五關、永遠一起查），不是像文件簽核那樣可變長度的步驟表。任何一關退回整筆終止，需重新送一筆新的。

## API

- `projects/:projectId/quotation-items`：CRUD + reorder + `apply-target`（設定目標毛利率或目標總金額，一次性回推所有/選取工項的單價）。
- `projects/:projectId/procurement-comparisons`：CRUD + 廠商報價 CRUD + 附件上傳 + 選定得標廠商。
- `projects/:projectId/cost-control-rows`：CRUD + reorder + 設定勾選工項 + 拆項表（`/breakdown`）+ 追加減紀錄。
- `projects/:projectId/payment-requests`：list/get/create。
- `payment-requests`（跨專案）：`/pending` 待我簽核佇列 + `/:id/stages/:stage/decide` 逐關核准/退回，簽核關卡的權限判斷是「這關的負責人本人」，不是專案存取權，所以獨立不掛在 `projects/:id` 底下。

`tsc --noEmit`、既有 60 個 API 單元測試全過。
