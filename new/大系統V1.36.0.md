# 大系統 V1.36.0（2026-08-04）

延續 V1.35.0，LINE 新增「條列式一次登陸多筆」功能。

## 使用者需求

「代辦事項我希望不要一項一項登記，包括記帳、投資等所有能登陸的功能都可以條列式的登陸例如1.XX XXX XXX2.XX XXX XXX」——確認範圍：代辦、記帳、股票、行事曆四種「登陸」指令一次做齊；每行前面的「1.」「2、」編號有沒有都行，有就自動剝掉；處理完回覆要逐行列出成功/失敗。

## 設計

現有四個「登陸」指令（`tryFinanceCommand`/`tryStockCommand`/`createTodoFromText`/`createCalendarEventFromText`）原本都是直接呼叫 `this.reply(replyToken, ...)` 回覆，一個 replyToken 只能用一次，沒辦法讓同一則訊息拆成好幾筆分別回覆。改法：

- 四個方法的 `replyToken: string` 參數改成 `Responder`（`(text: string) => Promise<void>`）型別，內部呼叫改成 `respond(...)`，不直接碰 `this.reply`。
- 單行模式（原本的行為）呼叫端傳 `(msg) => this.reply(replyToken, msg)`，行為完全不變。
- `handleTextForLinkedUser` 新增批次判斷：把訊息用換行拆成多行、去掉空行，如果有 2 行以上，逐行呼叫新的 `tryBatchLine`（先剝掉行首選用的「N.」「N、」「N-」編號，再依序試「新增行事曆」→「新增」(代辦)→「買股/賣股」→「支出/收入」四種前綴，用一個把訊息收進陣列而不是真的回 LINE 的 capture responder），把每行結果收集起來，編號後合併成一則回覆一次送出。
- 批次判斷刻意放在網址擷取（知識庫）之後，避免「連結+說明文字」分兩行貼過來時被誤判成批次而漏掉分析。
- 選單類/查詢類指令（代辦事項、記帳、股票買賣說明、代辦事項總覽…）不算「登陸」指令，多行模式下如果某一行剛好是這類關鍵字，就是看不懂——這是預期行為，批次功能只管四種會真的寫入資料庫的登陸指令。
