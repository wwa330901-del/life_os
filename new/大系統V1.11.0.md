## 三、前端變動

- 移除 `admin_project_options_screen.dart`、`project_options_provider.dart`、`ProjectOption` model 等對應的死碼，平台管理後台首頁拿掉「專案類型/狀態管理」那張卡片。
- `admin_spaces_screen.dart`/`AdminSpaceSummary` 簡化，因為後端已經不會回傳個人空間，拿掉 `type`/`personalOwnerName` 相關的分支判斷。
- `admin_space_detail_screen.dart` 的「新增成員」對話框改用 `Autocomplete<AdminUserSummary>`，資料來源重用「帳號管理」畫面已經在用的 `adminUsersProvider`（可用姓名/帳號/email 搜尋），並過濾掉已經是這個空間成員的帳號，不用再手打 username。
- `app_sidebar.dart`（原本點使用者名字是登出）拆成「個人設定」（跳對話框呼叫新的 `PATCH auth/me`）跟「登出」兩顆按鈕。
- **`project_info_tab.dart`**：欄位固定顯示順序改成 案號、業主名稱、案名、專案地點、類型、狀態、簽約日期、預計結案日（新增了原本沒有的可編輯「案名」欄位，綁 `project.name`）；新增 `_reservedPropertyNames`（排除「簽約日期」「預計結案日」）避免同名自訂屬性又跟固定欄位重複顯示；任何空間額外自訂的屬性照舊排在最後，不會消失。
- **`task_table.dart`**（工期表左側的工項清單）：
  1. 表頭跟資料列之間的「前導留白」（拖曳把手/收合按鈕/色條/間距）補齊一致（`_leadingGutterWidth`）。
  2. 表頭五個欄位標題全部改成置中（`textAlign: TextAlign.center`）。
  3. **結構性修正**：深度縮排（`depth * _indentWidth`）原本是畫在名稱欄位「前面」的一個 sibling `SizedBox`，會讓整列的固定寬度往右長，導致越深層的子項目、後面的起始日/結束日/工期/相依欄位跟淺層項目對不齊。改成把縮排包進名稱欄位「內部」（一個內嵌的 `Row`），讓名稱欄位本身的寬度在任何深度都保持不變，後面所有欄位不管第幾層都會落在同一個 x 位置。
  4. 母項目（`isParentRow`）跟一般工項在各欄的 padding 不一致（母項目多包了一層 `Padding(horizontal:4)`，一般工項是 flush-left 或 TextField 預設的隱性 padding）——統一成 flush-left（`TextField` 額外指定 `contentPadding: EdgeInsets.zero`，「相依」欄位的 `TextButton` 加 `alignment: Alignment.centerLeft` 避免文字被置中）。
- **`app_sidebar.dart` 新增可隱藏側邊欄**：新增 `sidebarCollapsedProvider`（`lib/state/ui_prefs_provider.dart`，記憶體狀態，重開 App 會重置成展開）。收合時側邊欄縮成一條 14px 寬的 rail；滑鼠移到 rail 上用 `CompositedTransformTarget`/`CompositedTransformFollower` + `Overlay` 彈出完整寬度（220px）的側邊欄浮層（蓋在內容區上面，不是把內容區推開），移出滑鼠後延遲 200ms 收回（避免滑鼠移動到浮層本身時誤判成離開）；側邊欄頂部有一顆圖釘按鈕，收合狀態下點擊會固定展開（同時關掉浮層），展開狀態下點擊會收合成 rail。

## 四、Windows 打包流程 bug（重要，影響所有未來發版）

`flutter build windows --release` 是「增量編譯」——如果不先清掉 `apps/windows_app/build/windows`，CMake 有時不會重新產生 exe 內嵌的 Win32 版本資源（`Runner.rc`），導致即使 `pubspec.yaml` 的版本號已經改了、程式碼也真的重新編譯了，`package_info_plus`（App 內建更新檢查讀取「目前版本」用的套件）讀到的還是舊版本號。結果：App 永遠覺得自己版本比 GitHub 上的新版舊，即使使用者裝了新安裝檔還是一直跳「有更新」的提示——因為新安裝檔裡的 exe 版本號其實也還是凍結的舊值。

**已經補進發布流程**：每次發版前，`flutter build windows --release` 之前一定要先 `rm -rf apps/windows_app/build/windows`，編完之後用 PowerShell `(Get-Item apps\windows_app\build\windows\x64\runner\Release\life_os_app.exe).VersionInfo.FileVersion` 確認真的等於 `pubspec.yaml` 的版本號，才進到打包安裝檔那一步。詳細除錯過程記錄在 `docs/問題排除紀錄.md`（2026-07-28 那條）。v0.11.2/v0.12.0 這兩版可能也曾經默默踩過這個坑（沒被發現），只有這次的 v0.13.0 是確認修好、重新上傳過的。

## 六、發布流程（更新，新增清空 build 目錄這一步）

1. commit + push 程式碼
2. 版本號同步改 `apps/windows_app/pubspec.yaml` 與 `apps/windows_app/installer/life_os.iss`
3. **`rm -rf apps/windows_app/build/windows`**（新增，避免版本號被增量編譯凍結）
4. `flutter build windows --release`
5. **確認版本號**：`(Get-Item apps\windows_app\build\windows\x64\runner\Release\life_os_app.exe).VersionInfo.FileVersion` 必須等於 pubspec 版本，不一致就回到第 3 步重來
6. `"C:\Users\chen6\AppData\Local\Programs\Inno Setup 6\ISCC.exe" installer\life_os.iss`
7. `gh release create vX.Y.Z installer/Output/life_os_setup.exe --title vX.Y.Z --notes "..."`
