# 大系統 V1.43.0（2026-08-05）

修正知識庫項目列表沒有分頁上限的問題（2026-08-04 通盤檢討找到的低優先度項目之一，這次先處理）。

## 問題

`KnowledgeItemsService.listOwn`／`listPublicFromOthers`（`apps/api/src/knowledge/knowledge-items.service.ts`）過去沒有任何 `take`/`skip` 限制，選「全部分類」時會把使用者名下（或看得到的公開）所有知識庫項目一次抓出來、一次全部渲染在 App 的 `ListView` 裡。目前項目數量還不多感覺不出來，但長期下來資料量一多，這個「全部分類」選項會越來越慢，最壞情況可能讓 App 卡住/當機。選定單一分類（等於隱藏掉其他分類的列）目前是唯一能限制資料量的方式，但這只是繞過問題，不是真正的修法。

## 修正

- **後端**：`listOwn`／`listPublicFromOthers` 改成以 `id` 做游標分頁（`orderBy: createdAt desc, id desc` 保證同時間戳記的資料也能穩定排序），預設每頁 30 筆，回傳格式從純陣列改成 `{ items, nextCursor }`。`GET /knowledge/items`／`GET /knowledge/items/public` 新增 `cursor` query 參數。公開區的封鎖名單過濾維持在分頁**之後**才套用，避免影響 `nextCursor` 的正確性。
- **App**：`knowledge_provider.dart` 的 `knowledgeItemsProvider`／`publicKnowledgeItemsProvider` 從 `FutureProvider.family` 改成 `AsyncNotifierProvider.family`（`KnowledgeItemsPageState` 累積已載入的項目＋游標＋`hasMore`），私人區／公開區兩個分頁畫面都加上 `ScrollController`，捲到底部前 200px 時自動載入下一批（無限捲動），列表底部顯示載入中的轉圈。切換分類/搜尋條件時，因為是不同的 family key，會自動重新從第一頁開始，不需要額外重置邏輯。

`flutter analyze`、`tsc --noEmit`、既有 51 個 API 單元測試全過。

## 發布

App 端有實際變動（無限捲動行為），版號依慣例升到 2.9.1，隨附安裝檔更新。
