# 大系統 V1.69.0（2026-08-11）

行事曆空間新增 iCloud 日曆連結（v2.9.21）。

## 背景

使用者的 iPhone 用 iCloud（Apple 內建的提醒事項/日曆），同事共用了一個「工作」行事曆給他，之前系統只有跟 Google 日曆整合，沒辦法把 iCloud 這邊的行程拉進元序看。

## 設計

- 走 CalDAV 協定（iCloud 開放的標準日曆存取方式），使用者提供 Apple ID + 一組「App 專用密碼」（appleid.apple.com 產生，不是登入密碼——iCloud 全面強制雙重驗證，一般密碼沒辦法直接打 API）。
- **只單向匯入**（iCloud → 元序），不會把元序自己新增的行程推回 iCloud——跟既有的「代辦事項 → 行事曆」單向同步是同一個設計哲學，比雙向同步簡單、風險也低。
- 連結分兩步：先用帳密去列出這個 Apple ID 底下能看到的所有日曆（含同事分享、已經接受的——iCloud 在伺服器端處理分享，接受後就直接算這個帳號自己的日曆之一，不需要特別處理），使用者勾選要匯入哪幾個才會真的存進資料庫、開始同步。
- 匯入的行程直接放進使用者現有的「行事曆」空間，跟自己新增的行程、代辦事項同步過來的行程混在一起顯示，不特別做來源顏色標示（跟現有 Google 同步的行程一樣，沒有視覺區分）。
- 每 5 分鐘背景排程自動重新拉一次（過去 7 天～未來 90 天的固定時間窗），iCloud 那邊的重複行程（RRULE）在匯入時就展開成一筆一筆具體事件，不用元序自己的重複行程系統表示（兩者格式落差太大，硬轉換容易失真）。
- 取消連結時，之前匯入的行程會一併清掉。

## 實作

- 新 npm 套件：`tsdav`（CalDAV 客戶端）、`node-ical`（ICS 解析，含 RRULE 展開）。
- 新 model `AppleCalendarConnection`；`CalendarEvent` 新增 `appleEventUid` 欄位（跟既有的 `googleEventId` 並列，各自獨立）。
- 新服務 `AppleCalendarService`（低階 CalDAV 存取：驗證帳密、列日曆、抓事件原始 ICS）、`AppleCalendarSyncService`（解析 + 寫入資料庫 + 5 分鐘排程）。
- 新路由 `spaces/:spaceId/calendar/apple/{connection,discover,connect,sync}`。
- App 端：行事曆畫面標題列新增「連結 iCloud 日曆」按鈕，跟既有的 Google 按鈕並排。

`tsc --noEmit`、既有 60 個 API 單元測試全過、本機完整啟動確認路由掛載正常（過去踩過模組匯出漏掉導致啟動失敗的坑，這次先本機驗證過才推）。`flutter analyze` 乾淨。

## 尚未實機驗證

沒有真實的 iCloud 帳密可以在這裡測試，功能是照 CalDAV/node-ical 的標準用法寫的，但實際連上 iCloud、抓到真的事件、重複行程展開是否符合預期，需要使用者拿自己的 Apple ID + App 專用密碼實際連結測試一次才能確認。
