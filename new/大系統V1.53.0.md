# 大系統 V1.53.0（2026-08-05，純後端）

持股計算改用快取表。

## 問題

`StocksHoldingsService.list()` 每次被叫（首頁小工具、LINE 持股總覽、App 持股總覽分頁）都是重新把整個空間所有股票代碼的完整交易史重算一次平均成本——跟之前修過的知識庫/代辦事項是同一類「無上限查詢」問題，但這裡不能用分頁解，因為平均成本法本身是「順序相依」的（實測驗證過：同一組買賣交易換個順序，算出來的最終成本基礎會不一樣），沒辦法只靠限制查詢筆數來讓它變快又對。

## 修正

- 新增 `StockHolding` 快取表（`spaceId` + `stockCode` 唯一），存目前股數與成本基礎。
- `StocksHoldingsService.recompute(spaceId, stockCode)`：針對「一個空間的一支股票」做完整的時間序（`tradeDate` 排序）走訪重算，股數歸零就直接刪快取列。`list()` 現在只單純讀這張快取表，不再重算。
- 每個會動到 `StockTransaction` 的地方，寫入後都補呼叫 `recompute`：`StocksTransactionsService.create/update/remove`、`StocksRecurringService.fulfillPendingReply`（定期定額成交回覆）。
- 刻意選擇「每次都整支股票全部重算」而不是「只套用這筆新交易的增量」——因為補登的交易 `tradeDate` 可以是任何時間點，不保證新建的那筆在時間序上一定是最後一筆，只有整段重走一次才對。
- **既有資料的回填**：這次沒有另外寫一次性回填腳本手動跑正式環境資料庫。改成讓 `list()` 自我修復——如果一個空間有交易紀錄但快取表是空的（代表這個空間還沒被這次改動碰過），第一次讀的時候就會自動把這個空間交易過的每支股票都 `recompute` 一次填好快取，之後就都是純讀快取。所以上線後每個使用者第一次打開「持股總覽」會稍微觸發一次背景重算，之後就跟平常一樣快。

`tsc --noEmit` 乾淨、既有 51 個 API 單元測試全過。首頁小工具（`home.service.ts`）跟 LINE 持股總覽（`line.service.ts`）都只是呼叫 `list()` 拿陣列，回傳格式完全沒變，不用改。
