## 簽核系統設計要點（皆經 AskUserQuestion 逐項確認）

- **開關**：文件範本可個別手動設定「需要簽核」（預設關閉）。系統**不會**解析文件編號規則（01對外/02對內/03合約）自動判斷，純手動設定。
- **簽核目標**：對「已產出的文件」(`GeneratedDocument`) 送簽，不是對範本本身。
- **送簽權限**：僅限文件建立者本人。
- **簽核關卡**：送簽當下才指定，依序多關，每一關從同一個公司空間成員中挑選（不是範本固定的角色）。
- **目前該誰簽**：即時計算（最小序號且尚未 APPROVED、前面關卡都已 APPROVED 的那一關），不落地儲存，避免狀態漂移風險。
- **簽核人動作**：
  - 核准：可填簽核說明（選填），推進到下一關。
  - 退回：必填退回原因，直接結束整個簽核流程（不可恢復），承辦人修改文件後需重新送一次全新的簽核。
  - 提問補充：不退回，通知承辦人補充說明；承辦人回覆後該關卡狀態不變，簽核人可繼續正常決定。
- **鎖定**：全部關卡核准後，該文件鎖定，不可刪除。
- **通知**：送簽、核准、退回、提問、回覆等每個關鍵節點都會透過 LINE 通知對應人員。

## 實作重點

- Prisma：新增 `DocumentApproval`／`DocumentApprovalStep`／`DocumentApprovalStepNote` 三張表，`DocumentTemplate.requiresApproval`。
- Server 端 `assertCurrentStep` 用 `count` 查詢「前面是否有未核准的關卡」判斷是否輪到你，不維護額外指標欄位。
- Flutter 新增「簽核」側邊欄項目（僅公司空間顯示）：待我簽核／我送出的兩個分頁；文件管理頁面依狀態顯示「送簽」「簽核歷程」按鈕與狀態標籤，核准鎖定後隱藏刪除選項。
