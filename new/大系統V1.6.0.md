## 一、起因

使用者實際點過工期分頁後回報兩件事：「用起來很卡頓」、「很多功能沒轉移過來」。過程中使用者又追加一個更強烈的回饋：「整個軟體版面排版這次一起修改，你現在做的我越看越陽春，太低端了，我要的是這是一個高端的軟體」。這一版就是同時處理這兩條線。

## 二、效能修正

`ProjectEditorNotifier._fetch()`（`apps/windows_app/lib/state/project_editor_provider.dart`）原本用三次依序 `await` 的 GET 重新整理專案/工項/排程，每次編輯都要跑一輪，是卡頓的主因。改成 `Future.wait` 平行送出，等待時間減少約 2/3。

## 三、工期分頁補齊的四個功能

對照 reno_pm 原始碼確認：縮放、匯出是 reno_pm 本來就有、移植時跳過的；**甘特圖直接拖曳改日期是 reno_pm 也沒有的全新功能**；復原/重做 reno_pm 有，但機制是「整個 Project 快照堆疊」，在多人協作的雲端模型下不安全（快照式復原可能蓋掉別人剛做的變更），這次改成**動作式復原**（見下）。

1. **甘特圖縮放**：移植 reno_pm 的 `ui_prefs_provider.dart`（12-80px，每次 ±8px），`GanttTimeline` 原本就支援 `dayWidth` 參數只是沒人傳值。
2. **甘特圖水平捲軸**：加上可見、可拖曳的 `Scrollbar`（原本捲動機制存在但完全沒有視覺提示，使用者不知道可以左右滑）。
3. **甘特圖直接拖曳改日期/工期**：`GanttTimeline` 的 Positioned 疊圖偵測拖曳位置（bar 本體=搬移起始日，右緣 8px=調整工期），放開時才呼叫既有的 `changeStartDate`/`changeDuration` API（跟任務表格的日期選擇器是同一組語意），拖曳中純本地繪製半透明預覽疊圖（`GanttPainter` 新增 `dragPreview` 參數）。
4. **復原/重做（Ctrl+Z/Ctrl+Y）**：新增 `lib/state/edit_history.dart`，每種操作（改名/工期/日期/前置工項/公休日曆/新增/刪除/排序）各自記錄「舊值」而非整包快照，undo 時呼叫既有 API 方法把值改回去 —— 永遠是對「當下伺服器狀態」的一次新合法寫入，不會覆蓋別人剛做的變更。已知取捨：復原刪除會用新的伺服器 id 重建項目，如果更早的歷史紀錄剛好引用舊 id 會安全地失敗（既有的錯誤處理會顯示提示，不會讓畫面壞掉）。
5. **匯出 PDF/PNG**：移植 `gantt_export_painter.dart`（直接複用 `GanttPainter`/`GanttHeaderPainter`）、`image_export_service.dart`、`pdf_export_service.dart`、`export_controller.dart`、`export_options_dialog.dart`。life_os 依然是 Windows 桌面 App（只是資料來源換成雲端 API），檔案輸出（`file_selector` 原生存檔對話框）完全不用改。新增套件：`pdf`、`file_selector`、`image`。

## 四、全站排版重新設計

用了兩輪 HTML/CSS mockup 讓使用者比較（不是直接改 code）：先比色彩字體方向（使用者選了 Notion 式溫暖極簡，但明確說「更看重排版而不是色彩字形」），再比排版骨架（常駐側欄＋儀表板網格，取代手機式單欄清單）。

**核心架構**：新增 `lib/ui/shell/space_shell.dart`（常駐側欄 `app_sidebar.dart` ＋ 內容區），取代 `app.dart` 的 `_RootRouter` 原本選定空間後直接顯示的 `HomeScreen()`。內容區用單純 local state（`_activeModule`/`_openProjectId`）切換儀表板/專案清單/專案詳情，完全沿用 `_RootRouter` 本來就有的「依 state 切換整個畫面」風格，沒有引入 Navigator 路由重構。

- `home_screen.dart` 拆解為 `lib/ui/shell/dashboard_view.dart`（儀表板，只顯示真的存在的模組，不做假的「即將推出」佔位卡片）
- `project_list_screen.dart`／`project_detail_screen.dart` 拆掉各自的 `Scaffold`/`AppBar`，改用共用的 `lib/ui/shell/breadcrumb_bar.dart`；專案清單從 `ListView`+FAB 改成卡片網格+固定按鈕
- `space_picker_screen.dart` 從拉伸滿版的清單改成置中定寬卡片
- `app_theme.dart`：卡片/對話框陰影從「無陰影+邊框」改成暖色調柔光陰影，圓角從 20px 收到 14px
- 新增 `app_accents.dart`（個人/公司空間圖示色塊）
- **實際建置後截圖驗證抓到一個既有問題**：`AppGradients`（登入頁/首頁背景漸層）原本是寫死的亮色數值，在系統深色模式下會跟深色卡片打架，已經改成跟著明暗模式走

放棄的想法：自訂襯線標題字體（Flutter Windows App 內嵌完整字重的中文襯線字型成本偏高，這次把「高端感」放在排版結構/陰影深度/留白，之後有需要可以再評估）。

## 五、驗證方式與限制

`flutter analyze` 全程乾淨、`flutter build windows --release` 成功。這台機器 OS 層級滑鼠自動化不可靠，用 PowerShell 直接啟動 exe + 截圖驗證了空間選擇頁在深色模式下正確渲染，但側欄殼層/儀表板/專案清單/專案詳情這幾個新畫面、以及拖曳手勢/鍵盤快捷鍵/原生存檔對話框，都還沒有真人點過一遍 —— **下次要做的事：使用者實際點一輪整個新排版，特別看側欄寬窄/間距、麵包屑導覽、拖曳甘特圖、Ctrl+Z/Y、匯出對話框，回報有沒有問題。**

## 六、發布流程（沿用）

1. commit + push 程式碼
2. 版本號同步改 `apps/windows_app/pubspec.yaml` 與 `apps/windows_app/installer/life_os.iss`
3. `flutter build windows --release`
4. `"C:\Users\chen6\AppData\Local\Programs\Inno Setup 6\ISCC.exe" installer\life_os.iss`
5. `gh release create vX.Y.Z installer/Output/life_os_setup.exe --title vX.Y.Z --notes "..."`
