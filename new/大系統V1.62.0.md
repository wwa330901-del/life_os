# 大系統 V1.62.0（2026-08-06，純後端）

知識庫 Instagram 連結分析（cookie 版）。

## 背景

一開始的計畫是讓後端自動登入 IG（Playwright 模擬瀏覽器 + 一次性驗證碼），但實測發現：不管帳密多正確，從這個開發環境自動登入都會被 Instagram 的防機器人機制擋下來（顯示「帳密錯誤」，但帳號本身用真人瀏覽器登入完全正常）。這是環境層級的風控，不是帳號問題，換到 Render 的伺服器上大概率會撞到同一道牆。

改用更務實的做法：不讓程式自動登入，直接拿使用者自己瀏覽器裡「已經登入」的 session cookie（`sessionid`）給後端用。這樣完全不會觸發「自動化登入」這個會被盯上的動作——就是一般已登入使用者的正常請求而已。

## 修正

- 新增 `InstagramFetcherService`：帶著 `sessionid` cookie 抓 IG 貼文頁面，解析 `og:title`/`og:description`/`og:image`/`og:video` meta tag 拿到文字/圖片/影片，跟原本 `ContentFetcherService.extractArticle` 同一套 cheerio 解析手法。
- `ContentFetcherService.fetchFromUrl` 遇到 IG 連結時，改成呼叫 `InstagramFetcherService`（沒設定 `INSTAGRAM_SESSION_ID` 才退回原本「不支援」的訊息）。
- Session 會過期（不會自動更新），過期時回覆清楚的錯誤訊息，需要使用者重新從瀏覽器複製一組新的 `sessionid` 更新到 Render 環境變數。

`tsc --noEmit`、既有 60 個 API 單元測試全過。

## 發布

純後端修正，Windows App 端沒有任何程式碼變動——不隨附安裝檔更新，直接 commit + push 讓 Render 重新部署即可生效。**需要在 Render 設定環境變數 `INSTAGRAM_SESSION_ID`**（從瀏覽器 DevTools 的 Application → Cookies → instagram.com 複製 `sessionid` 的值）才會真的動起來。
