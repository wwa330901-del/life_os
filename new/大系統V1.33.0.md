## 公司空間管理：三個真實問題

使用者一次回報 5 點，逐一排查：

1. **不能自己刪除空間**——確認過去真的沒有這個功能（`SpacesController` 完全沒有 DELETE 路由）。確認設計：只有 OWNER 能刪，且要在確認對話框裡輸入完整空間名稱才能按下「永久刪除」。刪除會連帶砍掉裡面所有專案（進而連鎖砍工項/成員/代辦事項/文件/簽核紀錄）。實作：`SpacesService.remove`——`Project.spaceId`/`CompanyMembership.spaceId` 是全部 Space 關聯裡僅有的兩個 `ON DELETE RESTRICT`（其餘都是 Cascade），所以要先手動 `deleteMany` 這兩張表，Space 本身才刪得掉；包在一個 `$transaction` 裡。App 端新增「刪除空間」在側邊欄（紅色文字），只有 `space.role === 'OWNER'` 才顯示。

2. **新增空間後沒有設定讓我選擇要甚麼系統** + **3. 專案資料表屬性沒辦法設定，全沒了**——追查後這兩個是同一個根本原因：`AdminService.createCompanySpace` 建立空間時**從來沒有把建立者自己加進 `CompanyMembership`**，導致新空間建好當下，任何人（包括建立它的平台管理員自己）都還不是這個空間的成員。`ProjectPropertiesService.assertCanManage` 要求呼叫者是該空間的 OWNER/ADMIN，一個非成員的呼叫者點「新增屬性」就會被 403 擋下——這正是使用者說「屬性畫面一片空白、不知道怎麼新增」的真正原因，不是介面設計不夠直覺，是背後權限真的不通。**修法**：`createCompanySpace` 改成建立當下就把呼叫者（平台管理員）加成 OWNER。修好之後空間建立完就能馬上用，使用者確認不需要再做「建空間時選擇啟用哪些模組」這個額外功能。

3. **在某公司專案裡點另一個公司空間，畫面不會自動跳出去**——這是真的 UI bug，已修好。`SpaceShell` 是 `_RootRouter` 重複使用的同一個 widget 實例（不管選哪個空間都是同一個 `const SpaceShell()`），內部的 `_openProjectId` 等 local state 只在 `_backToList` 等操作被呼叫時才重置——切換到不同公司空間本身不會觸發，所以卡在舊空間的專案畫面。修法：`_SpaceShellState` 新增 `_stateForSpaceId` 追蹤欄位，`build()` 一開始比對 `space.id` 是否變了，變了就重置所有 local 導覽狀態。

4. **「文件管理系統我要新增文件都只能丟到你這？」**——確認使用者想要的是「自己新增/上傳新範本」。查證現況：後端其實已經有 `POST /admin/spaces/:id/document-templates`（吃檔案+`fields` JSON），但這個端點設計上假設呼叫者已經手動把 `.docx` 用 `{{key}}` 標記好每個欄位、並準備好對應的 fields JSON（key/label/type/source/writesTo）——這是目前唯一由我（Claude）手動操作的步驟，App 裡完全沒有對應的上傳畫面。**這是一個獨立、有一定份量的新功能（檔案選取 + 動態欄位定義表單），這輪先不做，列為下一輪要設計的項目**，需要先討論欄位定義表單怎麼設計、`.docx` 標記方式要不要簡化等細節。
