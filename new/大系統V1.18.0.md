# 第 18 步：定期交易（每月自動記帳/LINE提醒）

## 零、給未來的我（Claude Code）

如果使用者說「我要寫大系統」，就是指這個系列文件（`new/大系統V1.1.0.md` ~ 目前最新版）跟 `C:\Users\chen6\Desktop\claude\life_os` 這個 monorepo。做法：

2. 直接在 `life_os` 目錄下繼續開發，延續「元序」這個產品
3. 每次程式有更動都要主動 commit + push 到 GitHub，不用使用者特別要求；使用者可見的改動還要照「發布流程」補做版本號/安裝檔/Release
4. 每次更新前後檢查 `life_os/problem feedback/` 資料夾裡有沒有使用者丟的截圖/回報
5. 需要視覺設計素材時，請使用者把圖片丟進 `life_os/Visual Design/`（這兩個資料夾都不進 git）
6. **Windows 發版前一定要先清掉 `apps/windows_app/build/windows` 再編譯**——這條寫過很多次了。

**這一版最重要的新東西：定期交易**——使用者問「信用卡消費怎麼記」，聊到「每個月要付信用卡費」才發現這個需求：某些交易會每個月固定重複發生（信用卡費、房租、訂閱），但金額不一定固定。設計上跟使用者確認過，選了「都支援」：

- **有填金額**（房租、訂閱這種固定數字）：到期當天系統直接幫你記一筆交易，並傳 LINE 通知「已自動記帳：XXX」。
- **沒填金額**（信用卡費這種每月數字不固定）：到期當天只傳 LINE 提醒「該處理 XXX 了」，不自動記帳，使用者自己去記實際金額。

## 一、資料模型

新增 `FinanceRecurringTransaction`（`apps/api/prisma/schema.prisma`）：`type`（INCOME/EXPENSE/TRANSFER，跟一般交易共用同一個 enum）、`amount`（可空，空代表金額不固定）、`accountId`/`toAccountId`/`categoryId`（規則跟一般交易一樣：TRANSFER 才用 toAccountId，其餘用 categoryId）、`dayOfMonth`（1-31）、`active`（可停用但不刪除）、`note`、`lastTriggeredMonth`（"YYYY-MM"，防止同一個月被排程重複觸發兩次）。

`dayOfMonth` 超過當月實際天數時（例如設 31 號，但 2 月只有 28/29 天），觸發日會夾到當月最後一天，不會整月都不觸發。

## 二、後端：CRUD + 每日排程 + LINE 主動推播

`FinanceRecurringTransactionsService`（`apps/api/src/finance/`）CRUD 邏輯跟既有的 `FinanceTransactionsService` 幾乎一樣，帳戶/分類的驗證規則直接重用同一份 `FinanceTransactionsService.validate`（原本是 private，這次改成可以被別的 service 呼叫，避免邏輯重複一份、以後容易drift）。

**每日排程**（`@Cron(CronExpression.EVERY_DAY_AT_9AM)`）：掃過所有 `active` 且這個月還沒觸發過的定期交易，`dayOfMonth`（夾到當月最後一天後）等於今天的就處理：有金額的直接 `financeTransaction.create` 一筆＋推播「已自動記帳」；沒金額的只推播提醒文字。處理完更新 `lastTriggeredMonth`，同一個月不會再觸發第二次——就算排程剛好跑了不只一次（或 Render 免費方案睡著又醒來、隔幾天才跑到這支）也不會重複記帳/重複通知。

**LINE 主動推播是新東西**：以前 LINE 這邊只有「回覆」（`reply`，一定要有進來的訊息帶的 `replyToken` 才能用），這次定期交易是排程觸發、不是使用者傳訊息觸發，沒有 `replyToken` 可用，要改用 LINE 的「推播」（`push`，用 `lineUserId` 直接主動發，不需要對應到某一則使用者訊息）。新增一個獨立的 `LineNotifierModule`/`LineNotifierService`（`apps/api/src/line-notifier/`），只負責這件事，刻意不放進 `LineModule` 裡——因為 `LineModule` 本來就依賴 `FinanceModule`（LINE 的財務總覽指令要用記帳的 service），如果定期交易又反過來讓 `FinanceModule` 依賴 `LineModule`，就會循環引用。獨立出一個沒有任何依賴的小 module，讓 `FinanceModule` 跟 `LineModule` 都能用，形成一個乾淨的單向依賴關係。

## 三、Windows App：定期交易分頁

記帳模組新增第六個分頁「定期交易」（`finance_recurring_tab.dart`）：列表顯示每筆的類型圖示、標題（有備註用備註、沒有就照分類/帳戶組出來，跟交易明細列表同一套邏輯）、「每月 X 日」＋「自動記帳 XXX」或「金額不固定，到期只提醒」、停用的會整列變灰。每一列可以直接用 Switch 停用/啟用（不用整個刪掉再重建）、編輯、刪除。

新增/編輯對話框幾乎照搬既有的交易編輯對話框（類型切換、帳戶/到帳戶/分類下拉選單），差異只有：多一個「每月第幾天」的數字輸入，「金額」欄位變成選填（留空＝金額不固定）。金額欄位從「有填」改成「留空」時，前端會用 `clearAmount: true` 明確告訴後端「把金額清空」，跟「這次沒有要改金額」（完全不送這個欄位）分開處理，不會搞混。

## 四、發布流程（沿用）

1. commit + push 程式碼
2. 版本號同步改 `apps/windows_app/pubspec.yaml` 與 `apps/windows_app/installer/life_os.iss`
3. `rm -rf apps/windows_app/build/windows`（一定要做）
4. `flutter build windows --release`
5. 確認版本號：`(Get-Item apps\windows_app\build\windows\x64\runner\Release\life_os_app.exe).VersionInfo.FileVersion` 必須等於 pubspec 版本
6. `"C:\Users\chen6\AppData\Local\Programs\Inno Setup 6\ISCC.exe" installer\life_os.iss`
7. `gh release create vX.Y.Z installer/Output/life_os_setup.exe --title vX.Y.Z --notes "..."`

**資料庫 migration**：本機沒有 Docker，用 `npx prisma migrate diff --from-config-datasource prisma.config.ts --to-schema prisma/schema.prisma --script`（帶正式環境 `DATABASE_URL`）產生 SQL，`npx prisma migrate deploy` 套用到正式環境。正式環境連線字串沒有存在任何本機檔案裡，每次需要都要請使用者重新提供；**使用者如果提到「換了資料庫密碼」，第一件事就是提醒去 Render 後台把 `DATABASE_URL` 跟著換掉**（見 V1.17.0 那次的教訓）。
