# 大系統 V1.24.0（2026-08-02）

延續 V1.23.0（知識庫 v2.0.0），同一天緊接著把 v2.0.0 release notes 裡明確列為「延後」的兩項做掉，發布為 `v2.1.0`。

## 背景

v2.0.0 發布時，我在 release notes 裡寫「需要設定 `GEMINI_API_KEY` 到 Render 環境變數」，使用者馬上抓到問題：「我如果申請好了放在render後端環境變數，不就變成大家都用我的?」——這句話點出這個做法根本違背「每個人自己付費」的初衷。所以這一輪要解決的：

1. 金鑰不能是系統層級共用設定，要改成**每個帳號自己的**。
2. 每個人自己去 Google 申請金鑰，沒有申請的人這個功能就是不能用，不做退回共用金鑰這種安全網。
3. App 裡要有申請步驟說明，讓其他使用者不用另外找文件、打開就知道怎麼做。
4. 每次 AI 分析要記錄用量（token/成本/耗時/狀態），每個人只看得到自己的紀錄，並且要分今日/本週/本月統計。

## 實作重點

- **移除共用金鑰**：`process.env.GEMINI_API_KEY` 整個拿掉，改成 `User.geminiApiKey`（存在使用者自己的帳號資料列，跟 `GoogleCalendarConnection.refreshToken` 一樣的明碼欄位慣例）。`GeminiContentAnalysisService` 不再在建構子裡建立一次性的 client，改成每次呼叫時用呼叫者自己的金鑰現建一個 `GoogleGenAI` client。
- **沒金鑰直接擋下**：`KnowledgeAnalysisPipeline.requireApiKey` 在做任何爬蟲/AI呼叫之前就先檢查，沒有金鑰就直接標記失敗、LINE 回覆請去 App 設定，不會浪費資源去抓網頁內容。
- **App「AI 設定」畫面**：side bar 新增一個入口，畫面裡同時放申請步驟（aistudio.google.com → Get API key → Create API key → 複製貼上）跟金鑰輸入欄位在同一頁，符合使用者說的「放在裡面」。
- **用量記錄**：新增 `AiUsageLog` 資料表，`feature` 欄位故意用字串不是列舉，方便以後其他 AI 功能共用同一張表。每次分析呼叫 Gemini 前後計時，成功記錄實際 token 數換算成本，失敗也記錄（0 token、狀態 FAILED、錯誤訊息）。App 知識庫頁面新增「用量記錄」分頁，顯示今日/本週/本月加總跟明細。

## 過程中的插曲

- 使用者問了一個很好的問題：既然要各自付費，那我要不要先跟你申請的示範一樣去 Google 申請一組？我先手把手帶使用者跑了一次申請流程（不涉及程式碼），確認清楚以後才繼續動工，避免使用者拿到金鑰卻发現放錯地方。
- 使用者另外反映 LINE 按鈕/指令現在會延遲很久才有反應，懷疑是 Render 免費方案休眠。確認是真的（Render 免費方案閒置約15分鐘會睡眠，喚醒要 30-60 秒，影響整個 LINE webhook，不只是知識庫），提供兩個方案（升級付費 vs 免費保活ping）讓使用者自己決定要不要處理、選哪個，**目前還沒有處理**，之後使用者提起再繼續。

## 發布

- 版本：Windows App `2.1.0+1`，安裝檔 `life_os_setup.exe`。
- GitHub Release：`v2.1.0`。
- 知識庫目前明確剩下的延後項目只剩一個：**獨立代辦事項空間**（可私人可公司），順便解決展覽提醒沒有代辦事項的問題。
