# 大系統 V1.66.0（2026-08-07，純後端）

行事曆全天行程跟 Google 日曆同步時會多跨一天到明天。

## 背景

Google Calendar API 全天事件的 `end.date` 是「不包含」語意（比實際最後一天多存一天，例如 8/7 一天的行程，Google 存的是 `start.date: 2026-08-07`、`end.date: 2026-08-08`），我們自己的 `endAt` 一直都是「包含」語意（8/7 一天的行程 `endAt` 就是 8/7 或 null）。推到 Google（`insertEvent`/`updateEvent`）跟從 Google 拉回來（背景同步，每 5 分鐘跑一次）這兩個方向都直接把日期原封不動地存過去，沒有做這一天的換算——所以只要行事曆空間有連 Google 日曆，新增的全天行程在下一次自動同步後，本機這邊的 `endAt` 就會被 Google 拉回來的資料蓋成多一天，行事曆畫面上看起來像整天行程跨到了隔天。

## 修正

- `GoogleCalendarService.toGoogleBody`：推到 Google 時全天事件的 `end.date` 改成 `+1` 天。
- `CalendarSyncService.applyRemoteEvent`：從 Google 拉回全天事件時，`end.date` 改成 `-1` 天換算回我們自己的「包含」語意。

`tsc --noEmit`、既有 60 個 API 單元測試全過。

## 已經被同步錯誤影響的舊資料

這個修正只讓「之後」的推送/同步正確，已經在資料庫裡被同步錯誤多跨一天的舊全天事件不會自動修正回來（沒辦法可靠分辨「本來就是多天的全天行程」跟「被同步錯誤多跨一天的」），需要使用者自己重新編輯、儲存一次那些事件，之後就會正確。

## 發布

純後端修正，Windows App 端沒有任何程式碼變動——不隨附安裝檔更新，直接 commit + push 讓 Render 重新部署即可生效。
