如果使用者說「我要寫大系統」，就是指這個系列文件（`new/大系統V1.1.0.md` ~ 目前最新版）跟 `C:\Users\chen6\Desktop\claude\life_os` 這個 monorepo。做法：

3. 每次程式有更動都要主動 commit + push 到 GitHub，不用使用者特別要求；使用者可見的改動還要照「發布流程」補做版本號/安裝檔/Release

**這一版最重要的新東西：**
1. **側邊欄直接列出所有空間**：原本要先點目前空間那一列才會跳出選單選其他空間，改成側邊欄直接把使用者所屬的每個空間都列出來，點哪個切哪個，不用多一次點擊。
2. **LINE「記帳」說明格式簡化**：拿掉「格式：類型 金額 分類 帳戶 備註(選填)...」跟備註相關的說明文字，只留一個範例；分類選項改成母分類後面接括號列出子分類（例如「飲食（早餐、午餐、晚餐）」），不再是看不出階層的純平鋪列表。

同時這一版還排查了一次「LINE 記帳/財務總覽完全沒反應」的回報，過程中意外發現使用者換了 Supabase 資料庫密碼、但 Render 的環境變數沒有跟著換，導致正式環境整個連不上資料庫（不只記帳，是全部功能都會壞），已排除；但這不是使用者最初回報的那個「沒反應」現象的根因，那個現象目前沒有抓到明確原因，只能觀察後續是否還會重現。

## 一、這次改動的起因

使用者這輪一次丟出三件事：

1. LINE「記帳」「財務總覽」點了完全沒反應
2. 帳號改名字的問題（後來確認是側邊欄本來就有的「個人設定」功能，使用者只是還沒發現）
3. 側邊欄要能直接列出所有空間選，不要再點開才能選（附了截圖，目前只有一個公司空間，看不太出「列表」的效果，但邏輯上是所有空間都會列出來）

## 二、LINE 記帳/財務總覽沒反應排查 + 資料庫密碼輪替的坑

**第一個假設（後來排除）**：v0.20.0 才新增的 `FinanceCategory.parentId` migration 沒套用到正式環境——這個專案在 2026-07-24 真的發生過 migration 沒套用的先例（見 `docs/問題排除紀錄.md`）。請使用者提供 Supabase Session Pooler 連線字串直接查證：`npx prisma migrate status` 顯示全部是最新的，用正式環境資料直接跑 `financeCategory`/`financeTransaction`（含 `include: category.parent`）查詢也都成功，排除這個假設。

**排查途中意外發現的真正問題**：使用者提到剛好也換了資料庫密碼，這時候測 `/auth/login` 發現正式環境從原本正常的 401 變成 500——**Supabase 換密碼不會自動同步到 Render 的 `DATABASE_URL` 環境變數**，這是這個專案第二次踩到「正式環境資料庫連線設定跟 Supabase 端脫鉤」這一類的坑（上一次是 migration 沒套用，這次是密碼過期，症狀一樣是查資料庫的動作全部 500）。請使用者到 Render 後台 Environment 頁面把 `DATABASE_URL` 的密碼換成新的、點「Save, rebuild, and deploy」，重新部署後 `/auth/login` 恢復回 401，資料庫連線問題排除。

**原始回報的根因**：資料庫問題排除後，使用者回報「記帳」確實有回應了——代表最初回報的「完全沒反應」，跟這次的資料庫密碼過期是不同時間點的兩件事，**真正原因沒有抓到明確結論**（可能是暫時性的、或跟 Render 免費方案閒置喚醒的冷啟動有關）。既然功能現在正常，先不繼續追，之後如果再發生，第一步就是去 Render Logs 找 `Failed to handle LINE event` 這行關鍵字（`LineService.handleEvents` 的 try/catch 目前只會把例外寫進 log，不會讓使用者在 LINE 上看到任何回覆，這是「完全沒反應」而不是「跳出錯誤訊息」的原因）。

## 三、LINE 記帳說明格式

`LineService.sendFinanceHelp`（`apps/api/src/line/line.service.ts`）原本的說明訊息會列「格式：類型 金額 分類 帳戶 備註(選填)，順序固定...」跟「其餘文字當備註」兩行說明，使用者覺得不需要，改成只留一行範例「例如「支出300午餐現金」」。

分類選項原本用 `leafCategories` 拿掉有子分類的母分類，直接平鋪列出所有可記帳的分類名稱，看不出哪些子分類是屬於哪個母分類。新增 `formatCategoryOptions`：以母分類（`parentId` 為空）為單位分組，每個母分類後面如果有子分類就接括號列出（`飲食（早餐、午餐、晚餐）`），沒有子分類的母分類維持單獨列出。記帳指令本身的解析邏輯（`leafCategories`／`parseFinanceCommand`）完全不受影響，使用者還是只打子分類（或沒有子分類的母分類）名稱，`formatCategoryOptions` 純粹是給說明訊息用的顯示層邏輯。

## 四、側邊欄直接列出所有空間

`AppSidebar`／`_SidebarPanel`（`apps/windows_app/lib/ui/shell/app_sidebar.dart`）原本是一個「目前空間」的單一列（圖示+名稱+一個切換小圖示），點下去才用 `showMenu` 彈出其他空間的選單。這次拿掉這個點擊-才-彈出的中間步驟，改成直接把 `mySpacesProvider` 拿到的所有空間都畫成一排 `_SpaceRow`（新元件，維持原本「彩色類型徽章＋名稱」的視覺樣式），目前選中的那個用主題色高亮、不能再點自己；最後固定加一個 `_SpaceRow.home` 回首頁。點其他空間直接呼叫 `selectedSpaceProvider.notifier.select(target)` 切過去，跟以前選單裡選的效果一樣，只是少了一次點擊。原本的 `_openSpaceSwitcher`（`showMenu` 彈出選單那段）整個刪除，改用不到的 `collection` 套件 import 也一併移除。

## 五、發布流程（沿用）

1. commit + push 程式碼
2. 版本號同步改 `apps/windows_app/pubspec.yaml` 與 `apps/windows_app/installer/life_os.iss`
3. `rm -rf apps/windows_app/build/windows`（一定要做）
4. `flutter build windows --release`
5. 確認版本號：`(Get-Item apps\windows_app\build\windows\x64\runner\Release\life_os_app.exe).VersionInfo.FileVersion` 必須等於 pubspec 版本
6. `"C:\Users\chen6\AppData\Local\Programs\Inno Setup 6\ISCC.exe" installer\life_os.iss`
7. `gh release create vX.Y.Z installer/Output/life_os_setup.exe --title vX.Y.Z --notes "..."`

**資料庫 migration**：本機沒有 Docker，用 `npx prisma migrate diff --from-config-datasource prisma.config.ts --to-schema prisma/schema.prisma --script`（帶正式環境 `DATABASE_URL`）產生 SQL，`npx prisma migrate deploy` 套用到正式環境。正式環境連線字串沒有存在任何本機檔案裡，每次需要都要請使用者重新提供。**使用者如果提到「換了資料庫密碼」，第一件事就是提醒去 Render 後台把 `DATABASE_URL` 跟著換掉**——這條這次又踩了一次，值得每次都主動確認而不是等使用者自己發現連不上。
