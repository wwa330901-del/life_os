# 大系統 V1.37.0（2026-08-04）

延續 V1.36.0，修好首頁「本日代辦事項」看不到今天到期項目的真正根因——一個影響範圍比想像中大的日期時區 bug。

## 使用者回報

「有個問題我首頁沒有顯示出我的代辦事項」——實際測試截圖也拍到了：代辦事項空間裡明明有兩筆截止 8/4（當天）的個人事項，首頁「本日代辦事項」小工具卻顯示「今日到期未完成（0）」。

## 排查過程

追到 `HomeService.todayRange()`：

```ts
function todayRange() {
  const now = new Date();
  const start = new Date(now.getFullYear(), now.getMonth(), now.getDate());
  const end = new Date(start.getTime() + 86400000);
  return { start, end };
}
```

這段完全沒有處理時區——`new Date()` 在伺服器（Render，UTC）上取到的是 UTC 的年月日，不是台灣的年月日。台灣時間每天 00:00～08:00 這段時間，UTC 都還停在前一天，所以伺服器算出來的「今天」範圍會整整晚台灣一天。代辦事項的 `dueDate` 是以「當天 UTC 午夜」存的（不管是 LINE 或 App 建立的，日期字串都會被解析成 UTC 午夜），這剛好落在伺服器誤判的「今天」範圍*之外*——這正是為什麼截圖那個時間點（台灣時間凌晨 2 點多）看不到「今天」到期的項目。

**這個坑這個專案其實踩過同一類問題**：`@Cron` 沒指定 `timeZone` 會用伺服器的 UTC 時間（V1.20.0 那次修過）、行事曆全天事件也曾經因為時區處理錯誤跨日（2026-07-31 修過）。這次是同一類問題換了個地方出現——只是這次不是排程觸發時間或跨日儲存，而是「今天」這個時間窗口本身算錯。

**影響範圍不只首頁**：全文搜尋後發現 `LineService` 裡至少還有兩處一模一樣的寫法：「財務總覽」的「今日收支」跟「代辦事項總覽」的「今日到期/未來7天」判斷，都有同樣的伺服器時區偏移問題——這幾個月來只要在台灣時間 00:00～08:00 之間用這幾個功能，都可能看不到理應顯示的「今天」資料。

## 修正

新增共用工具 `apps/api/src/common/taipei-date.ts`：

```ts
export function taipeiTodayRange(): { start: Date; end: Date } {
  const shifted = new Date(Date.now() + 8 * 60 * 60 * 1000);
  const start = new Date(
    Date.UTC(shifted.getUTCFullYear(), shifted.getUTCMonth(), shifted.getUTCDate()) - 8 * 60 * 60 * 1000,
  );
  return { start, end: new Date(start.getTime() + 86400000) };
}
```

不管伺服器自己的系統時區是什麼，都能正確算出「台灣現在這一天」對應的 UTC 時間範圍。同時提供 `taipeiCurrentMonth()`（給「財務總覽」的月份判斷用，同樣的道理，每個月 1 號的前 8 小時也可能算錯月份）。

三個受影響的地方全部改用這個共用工具：
- `HomeService.todayRange()`（首頁「本日代辦事項」「專案總表」共用）
- `LineService` 的「財務總覽」今日收支
- `LineService` 的「代辦事項總覽」今日到期/未來 7 天

`TodoDigestService`（早晚提醒）本身呼叫 `HomeService.getTodosToday`，這次一併修好，不用另外改。
