## 一、這次改動的起因

使用者提出：新增專案要填類型、狀態（下拉選單，選項像 Notion 資料庫的 select 屬性，由平台管理者設定）、業主名稱、專案地點（必填）、案號（選填），專案名稱自動組成「業主名稱+專案地點+類型」。同時要求「先把之前預留的系統欄位都拿掉」——追問後確認是指專案詳情頁還沒做內容、只顯示「即將推出」的四個分頁：**金額、合約條件、發包狀態、成本控制**。這四個拿掉，換成一個真正有內容的「專案資料」分頁。

**兩個我自己判斷、沒有再問使用者確認的地方**（如果後續使用者反應跟預期不同，回來檢查這裡）：
1. 類型/狀態選項是全平台共用一份（`isPlatformAdmin` 管理），不是每個空間各自一份
2. 「新增一個專案資料表」實際上是新增一個分頁承載這些欄位，不是另開一張跟 Project 平行的資料庫表

## 二、Prisma schema + migration

新增 `ProjectTypeOption`／`ProjectStatusOption` 兩個平台共用的選項表（跟 `CompanyMembership`/`ProjectMember` 一樣的 join-table 慣例，但這次是一對多）。`Project` 加 `typeId`/`statusId`（必填，關聯到選項表）、`caseNumber`（選填），`clientName`/`siteAddress` 從選填改必填。

Migration（`apps/api/prisma/migrations/20260725144436_add_project_type_status`）跟上一輪 `add_project_members` 一樣手動接資料回填：先建立兩個選項表 + 各插入一筆固定 UUID 的「未分類」預設選項，再把現有 Project 的 `clientName`/`siteAddress` 是 NULL 的補成空字串、`typeId`/`statusId` 全部指向「未分類」，最後才對這四個欄位加上 NOT NULL。本機用 Docker Postgres（`docker-compose.yml` 的 `life_os_postgres` 容器）驗證過，舊專案（`王公館室內裝修`）正確回填成「未分類/未分類」。

## 三、後端

- `CreateProjectDto`/`UpdateProjectDto` 加齊新欄位
- `ProjectsService.getProjectOrThrow` 統一加上 `include: {type, status}`（單一 row 的 join，不是新的 round trip），所有讀專案的地方（詳情、schedule、editor-state、work-items 授權檢查）都自動拿到 type/status 的完整物件，不用各自加 include
- 新增 `GET /project-options/types`、`GET /project-options/statuses`（任何登入使用者都能讀，下拉選單要用）
- 新增 `admin/project-options` 的新增/改名/刪除 CRUD（`PlatformAdminGuard` 保護），刪除前檢查有沒有專案還在用這個選項，有的話擋下來（跟「不能移除最後一位 PM」同一種保護邏輯）
- 全部用本機 Docker Postgres + curl 實測過：建立完整欄位的新專案、列表包含 type/status 物件、刪除使用中的選項被擋下來

## 四、前端

- `Project` model 補齊新欄位（`clientName`/`siteAddress` 改非空、新增 `caseNumber`/`type`/`status`）
- 新增專案對話框整個重寫（`create_project_dialog.dart`）：類型/狀態下拉、業主/地點必填、案號選填，專案名稱隨打字自動組成（業主+地點+類型），但只要使用者自己改過名稱欄位就不再覆蓋
- 新增「專案資料」分頁（`project_info_tab.dart`），取代四個「即將推出」佔位分頁，欄位都可以直接編輯（下拉即時送出、文字欄位失焦送出）
- 新增管理後台畫面（`admin_project_options_screen.dart`）管理類型/狀態選項清單，`admin_home_screen.dart` 加卡片連過去
- 專案清單卡片加上類型/狀態徽章

## 五、驗證方式與限制

後端：`npm test`（43 個測試全過）+ 本機 Docker Postgres 驗證 migration 回填 + curl 實測建立/列表/刪除保護。前端：`flutter analyze` 全程乾淨、`flutter build windows --release` 成功。這台機器滑鼠自動化不可靠，**新增專案對話框的下拉選單、專案資料分頁的即時編輯、管理後台的選項管理，都還沒有真人點過一輪**，下次要請使用者實際測試。
