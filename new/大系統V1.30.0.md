# 大系統 V1.30.0（2026-08-03）

延續 V1.29.0，同一天內兩件事：重新確認 Instagram 抓取方案、新增代辦事項早晚 LINE 提醒。

## Instagram 內容抓取 —— 重新討論後維持原決定

使用者提出「申辦一個帳號給 AI 登入」的想法，本質上就是 V1.29.0 已經討論過、當時明確否決的「用自己帳號的 session/cookie 登入抓取」方案的變形。盤點過其他選項：

1. **Instagram 官方 API（Graph API / oEmbed）**：只能讀使用者自己名下的貼文，別人發的 reel 完全存取不到，對「收藏別人分享的連結」這個需求無效。
2. **無頭瀏覽器帶登入態抓取**：技術包裝不同，但風險（觸發驗證挑戰、帳號被封）跟登入態抓取是同一類，沒有比較安全。
3. **付費第三方 IG 抓取服務**：V1.29.0 已否決。

跟使用者說明後，確認**維持現狀：改傳截圖**，不建立任何帳號、不接第三方服務。這不是程式改動，純粹是設計決策的再確認——**如果 Instagram 抓取需求再次被提起，直接引用這個結論，不用重新分析一次**。

## 代辦事項早晚 LINE 提醒（新功能，純後端）

使用者要求：早上 8:00 通知今日代辦事項，晚上 6:00 通知今天還有哪些未完成，且**工期表的工期資訊不要出現在這個通知裡**（跟既有「工項進度晚間提醒」，晚上 8:00 那則，是兩件事，刻意不合併）。

**確認的細節**（先問過使用者再動工）：
- 早上清單也只列「今天到期、尚未完成」的項目（不是列今天到期的全部項目）——所以早晚兩則本質上是同一個查詢在兩個時間點各推播一次。
- 清單為空時**照常發送**「今天沒有代辦事項」／「今天的都完成了」，不像工項進度提醒那樣沒事就不出聲——使用者明確要每天都看到一則訊息，確認系統還在跑。

**實作**：
- `HomeService.getTodosToday`（原本是 private，首頁儀表板「本日代辦事項」小工具在用）改成 public，供新服務重用，沿用同一個「今日到期＋未完成」的判斷邏輯，不重寫查詢。
- 新增 `TodoDigestService`（`apps/api/src/project-digest/todo-digest.service.ts`），註冊進既有的 `ProjectDigestModule`（跟 `ProjectDigestService` 同一個 module，共用 `HomeModule`/`LineNotifierModule` 的 import，沒有新建 module）。兩個 `@Cron`：`EVERY_DAY_AT_8AM` 跟 `EVERY_DAY_AT_6PM`，都帶 `{ timeZone: 'Asia/Taipei' }`（這個專案所有「特定時刻」的 cron 都要記得加這個，不然預設吃 Render 的 UTC）。
- 純粹是代辦事項清單，完全不查詢 `ScheduleService`/工期表資料，跟 `ProjectDigestService`（晚上 8:00 的工項進度延遲提醒）維持獨立，兩則訊息不會互相混雜內容。
