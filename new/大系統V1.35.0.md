# 大系統 V1.35.0（2026-08-04）

延續 V1.34.0，純後端兩項修正：知識庫支援 LINE 影片訊息、代辦事項早晚提醒改成分類分組格式。

## 1. LINE 傳影片，AI 從來沒分析過（截圖回報）

**讀到的資訊**：使用者傳一則螢幕錄影（01:15）到「元序生活」，App 知識庫私人區顯示「目前沒有資料」——完全沒有建立任何項目，連「等待分類決定」的暫存項目都沒有。

**根因**：`LineService.handleEvents` 只處理 `message.type === 'image'`（呼叫 `handleImageMessage`）跟 `'text'`（一般指令/網址），緊接著 `if (event.type !== 'message' || event.message?.type !== 'text') continue;` 這行會把包括 `'video'` 在內的任何其他訊息類型直接跳過——不回應、不記錄、連錯誤 log 都沒有。影片訊息從來就沒有被處理過，不是分析失敗，是整個流程從未被觸發。

**解法**：
- `LineService` 新增 `handleVideoMessage`，跟既有的 `handleImageMessage`平行，一樣呼叫 LINE 的 content API（`fetchLineMessageContent`，原本叫 `fetchLineImageContent`，重新命名成通用名稱，兩種訊息共用）下載影片位元組。
- `KnowledgeAnalysisPipeline` 新增 `processVideoSubmission`，跟 `processImageSubmission`平行。
- `ContentAnalysisInput`/`FetchedContent` 新增 `video?: { data: Buffer; mimeType: string }` 欄位——跟既有的 `youtubeUrl`（Gemini 直接用網址觀看 YouTube，不用上傳）是不同機制，這個是直接把影片位元組當 inline data 送給 Gemini，跟圖片走一樣的路。`GeminiContentAnalysisService.buildInputParts` 原本的 `GeminiInputPart` 型別早就定義了 `'video'` 這個 variant（原本只給 `youtubeUrl` 用 `uri` 形式），這次補上 `data`/`mime_type` 形式的用法。

## 2. 代辦事項早晚提醒改成分類分組、連續編號

使用者：「我希望每日通報代辦事項的時候不要再切換專案了，要就一次例如個人代辦1.XXX2.XXX3.XXX某某專案4.XXX5.XXX這樣」。

**改法**（`TodoDigestService.notifyUser`）：原本是不分組的扁平清單（`・標題（分類）`），改成依「個人」「各專案」分組、組間連續編號，格式：

```
☀️ 今日代辦事項

個人代辦：
1. XXX
2. XXX

測試：
3. XXX

傳「完成 編號」標記完成，或「改期 編號 新日期」改期。
```

順手把這個編號寫回 `LineAccountLink.lastTodoListIds`——這樣收到早晚提醒後可以直接傳「完成 3」或「改期 3 8/15」，不需要先傳「代辦事項」或「代辦事項總覽」重新查一次編號，也不用先「切換專案」到那個項目所在的專案才能操作。
