# 大系統 V1.29.0（2026-08-03）

延續 V1.28.0，使用者實際測試知識庫功能後回報三個問題，發布 `v2.3.0`。

## 使用者反饋

丟了一則 Instagram Reel 連結測試，AI 回覆的分析結果幾乎是空的（「建議點擊原始連結前往觀看」），且在 LINE 回覆現有分類名稱「星座」想手動歸類，卻被系統當成看不懂的指令。使用者提出兩個問題：

1. AI 應該真的進去分析連結內容（不論影片或文章），而不是只判斷「這是什麼類型」。
2. AI 判斷不出分類時，不論 LINE 或軟體內都要能手動分類。

## 排查過程

**問題2 先查到根因**：AI 判斷不出分類時會傳訊息叫使用者回覆分類名稱，但 `KnowledgeAnalysisPipeline` 忘了同步把 `LineAccountLink.pendingKnowledgeItemId` 設回去——`tryResolveKnowledgeCategoryDecision` 檢查這個欄位優先於一般指令解析，欄位沒被設值，使用者的回覆自然被當成一般指令，回「看不懂這個指令」。

**問題1 追查後發現不是 AI 的問題，是 Instagram 直接封鎖了外部存取**：直接用程式測試那則連結，不論一般網頁抓取還是 Instagram 官方「設計給第三方公開嵌入」的 embed 頁面，回傳的都是完全空白的通用頁面（`<title>Instagram</title>`，沒有任何 `og:` 標籤），代表沒登入的自動化存取已經被完全擋掉，不是抓取邏輯寫得不夠好的問題。跟使用者討論後確認：這是平台層級的封鎖，沒有不冒風險（自動登入帳號、付費第三方服務）就繞不過去，使用者最終選擇「改傳截圖」這個低成本、不受封鎖影響的替代方案（傳圖片本來就是直接讓 AI 看畫面本身，不經過任何網路抓取）。

## 修正

1. **`KnowledgeAnalysisPipeline`**：AI 判斷不出分類、推播訊息之前，補上 `this.prisma.lineAccountLink.updateMany({ where: { userId }, data: { pendingKnowledgeItemId: itemId } })`，讓後續的分類名稱回覆能正確對應到這筆資料。
2. **`ContentFetcherService`**：移除完全沒用的 `fetchInstagramPreview`（cheerio 抓 og 標籤，實測回傳永遠是空的），改為 export 一個共用的 `isInstagramUrl`/`INSTAGRAM_UNSUPPORTED_MESSAGE`；`LineService.captureKnowledgeUrl` 偵測到 Instagram 連結時直接引導改傳截圖，不再建立任何分析項目；`KnowledgeAnalysisPipeline.userFacingMessage` 也把這則訊息跟既有的「沒設定 API 金鑰」訊息一樣，排除在「這則知識庫內容分析失敗了：」這個通用包裝之外，直接原樣顯示。
   - 順手抓到並修掉一個舊漏洞：`KnowledgeItemsService.saveCopy`（App 裡「存一份到我的知識庫」）過去只建立 `PENDING` 項目，從沒真的呼叫 `KnowledgeAnalysisPipeline` 觸發分析，永遠卡在待處理狀態——這次一併補上觸發呼叫，並套用同一個 Instagram 檢查。
3. **App 知識庫項目詳細畫面新增「指定分類」**：`PATCH /knowledge/items/:itemId/category`（`KnowledgeItemsService.assignCategory`，驗證項目與分類都屬於呼叫者本人），不論項目目前是什麼狀態都能呼叫，同時也能拿來重新歸類已完成的項目。畫面上用一個簡單的 `SimpleDialog` 列出使用者自己的分類供選擇。
