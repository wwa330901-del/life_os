# 大系統 V1.71.0（2026-08-12）

股票定期定額大改版：到期自動先建待填成交價交易、立即扣款；手動股票交易改成股數優先輸入（v2.9.23）。

## 背景

使用者指出目前定期定額回覆方式（代碼／成交價／投入成本）不合理，也發現手動股票買賣的輸入方向（打投入成本、股數用算的）不符合實際操作習慣——券商成交回報一向是「成交價／股數」，不是要自己反推的總額。

## 定期定額新設計

- 新增每期投入金額（`monthlyAmount`，新增計畫時必填）。
- 到期（每天早上 9 點排程檢查）時**自動先建一筆「待填成交價」的交易**（會顯示在股票「交易紀錄」分頁），不再只是單純發個提醒——同時發 LINE 提醒「回覆『代碼 成交價』」。
- 回覆（LINE 或 App）只需要成交價，系統用「每期金額 ÷ 成交價」無條件捨去算出買得起的整股數，回推實際花費（可能略低於設定金額，捨去的零頭不會被記錄成任何形式的剩餘額度）。
- **立即扣款**：定期定額改成 T（不等 T+2 交割日、不等隔天早上的每日交割排程），回覆成交價的當下就直接完成交割——一般手動股票交易維持原本的 T+2 排程交割不變，只有定期定額是特例，因為到「回覆成交價」這一刻，早就已經超過真正該扣款的日子了。
- 待填成交價的交易也可以直接在「交易紀錄」分頁按「填入成交價」完成，不用透過定期定額分頁或 LINE。
- 待填成交價的交易不會被誤算進持股平均成本，也不會被交割排程誤扣款（都用新增的 `pending` 欄位排除）。
- 舊計畫（這次上線前建立的）在使用者重新編輯儲存、補上每期金額之前不會發提醒，避免用不存在的金額算出錯誤的東西。

## 手動股票買賣改成股數優先

- LINE「買股/賣股」跟 App 的「新增股票交易」表單，都從「代碼／成交價／投入成本」改成「代碼／成交價／股數」，金額（`totalCost`）自動算。

## 尚未實機驗證

這是大改版，雖然本機啟動、單元測試都過，但實際跑一輪「到期自動建待填交易 → 回覆成交價 → 立即扣款 → 持股/交易紀錄正確更新」的完整流程，還是需要使用者實際測一次（下一個扣款日，或手動改資料庫測試日期）才能真正確認。
