## 2026-07-24：Google 登入 / 密碼登入全部 500，且登入狀態不會保留

**使用者回報**：
1. 用 Google 無法登入
2. 希望 Google 登入的使用者只要沒登出，重開 App 不用再登入一次

**讀到的資訊**：
- 登入畫面截圖顯示 `Internal server error`（NestJS 對未攔截例外的預設訊息，代表後端某個地方直接炸掉，不是正常的驗證失敗訊息）
- 用不存在的帳號名稱測試 `/auth/login`（不需要真實帳密，任何查詢 User 資料表的動作都會踩到同一個問題）也回 500，代表連「查無此帳號」的正常錯誤路徑都跑不到，卡在資料庫查詢那一步
- Render 的 `Logs` 頁面關鍵字：`PrismaClientKnownRequestError`、`Authentication failed against the database server`、`password authentication failed for user "postgres"`、`code: 'P1000'`、`kind: 'AuthenticationFailed'`

**根本原因（其實是兩個疊在一起）**：
1. 當次部署新增了 `User.isPlatformAdmin` 欄位的 migration，但 Render 的部署流程**不會自動執行 `prisma migrate deploy`**——過去的 migration 是透過人工在有正式環境資料庫連線的情況下手動跑的，這次沒有人做這一步，所以正式環境資料庫其實沒有這個欄位。後來直接用 Supabase 的 Session Pooler 連線字串在本機跑 `npx prisma migrate deploy` 補上。
2. 為了要到連線字串，請使用者去 Supabase 重設了資料庫密碼，但 **Render 的 `DATABASE_URL` 環境變數不會跟著自動更新**，導致重設密碼之後 Render 端反而用舊密碼連不上（新的問題疊加在原本的問題上，一開始沒發現）。修正時又額外卡了兩個「人為操作」陷阱：
   - 編輯 Render 環境變數後，忘記按最下面的 **Save, rebuild, and deploy** 按鈕，改了等於沒改
   - 複製貼上連線字串時，密碼跟主機中間的 `@` 符號在貼上過程中遺失（`...Aq8Jaws-0-...` 少了一個 `@`），造成連線字串格式錯誤

**確認方式**：
- 直接用使用者提供的 Session Pooler 連線字串，在本機分別用 raw `pg` client 跟正式的 Prisma Client（同一份 generated client）連正式資料庫測試查詢，用來排除「是資料庫本身壞了」還是「只有 Render 那邊連不上」
- 用 `curl` 打 `/auth/login`（帶不存在的帳號）當作免帳密的健康檢查，重複測試不需要每次都等使用者操作 App

**最終解法**：
1. 本機執行 `DATABASE_URL="<正式環境連線字串>" npx prisma migrate deploy`（在 `apps/api` 目錄下）補上遺漏的 migration
2. 到 Render 後台 → `life-os-api` 服務 → Environment，把 `DATABASE_URL` 更新成當下正確的 Supabase Session Pooler 連線字串（`postgresql://postgres.<project-ref>:<密碼>@aws-0-<region>.pooler.supabase.com:5432/postgres`），存檔時務必點擊 **Save, rebuild, and deploy**（不是只按 Edit 旁邊那個沒有文字的存檔圖示）
3. 重新部署後用 `curl` 打 `/auth/login` 確認回應從 500 變成正常的 401「帳號密碼錯誤」

**以後遇到類似狀況可以先查**：
- 只要 Render log 出現 `password authentication failed` 或 `P1000`，先去 Environment 頁面把 `DATABASE_URL` 完整展開讀一次，不要只看有沒有存在，要逐字確認使用者名稱、密碼、`@`、主機名稱都在
- Supabase 重設資料庫密碼**不會**自動同步到任何外部服務（Render、本機 `.env` 等），改密碼之後要記得手動更新每一個用到這組連線字串的地方
- schema 有變更時，記得這個專案的 migration **不是**部署時自動套用的，要自己手動用正式環境連線字串跑 `prisma migrate deploy`（或未來考慮把它加進 Render 的 build/start command，一勞永逸解決這個坑）
